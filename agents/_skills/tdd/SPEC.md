# テスト駆動開発スキルの契約と設計根拠

このファイルは tdd skill の適用範囲、RED・GREEN・REFACTORの契約、検証方針、設計根拠を定義する保守契約です。実行時の詳細手順は [SKILL.md](./SKILL.md) に記載します。

## 適用範囲

対象は、テストによって変更の挙動を固定・検証する次の変更です。

- 新しいロジックやAPIの挙動の追加
- バグの再現と修正
- 既存の挙動、境界条件、エラー処理、互換性の変更
- 外部から見える挙動を維持するリファクタリング
- 挙動を変える設定変更の回帰検証

純粋な文書変更、挙動に影響しない静的設定、生成物の更新は対象外です。テストを先に書けない場合は、TDDを黙って省略せず、理由、代替検証、未確認の経路、残るリスクを報告します。

## TDDの契約

- 実装前に、変更する利用者向け挙動を観測可能なテストシナリオへ変換する。
- REDでは、最小のテストまたは再現テストが、期待する理由で失敗することを確認する。
- GREENでは、REDを通す最小限の実装だけを行い、未要求の一般化や無関係な整理を混ぜない。
- REFACTORはGREENを確認した後に行い、各変更の後でテストを再実行する。
- テストは内部実装の呼び出しではなく、結果、状態、出力、エラーなどの外部から観測できる契約を優先する。
- モックは、実装を直接使えない外部サービス、非決定的な依存、制御不能な副作用などに限定する。
- 最も狭いテストから開始し、関連テスト、境界・統合経路、全体テストへ検証範囲を広げる。
- テストがすぐに通った場合は、既存挙動を誤って再記述していないか、変更前の不具合を捕捉できるか確認する。
- 完了報告では、各サイクルのコマンドと結果、未検証の経路、実行できなかった確認を区別する。
- 実装全体、完了前検証、Git操作は、それぞれ対応する skill と明示的な依頼へ分ける。

## 対象外

- 文書、コメント、リンク、静的設定、生成物だけの変更で、実行時の挙動が変わらないもの
- 計画だけの依頼。計画は `task-planning` を使う
- TDDを理由にした未要求のプロダクト改善、テスト対象外の大規模リファクタリング
- テストを通すための期待値の弱体化、失敗テストの削除、テスト不能理由を隠した完了報告
- TDDの完了を理由にしたcommit、push、PR、merge、releaseなどのGit操作

## 維持・改善

`SKILL.md` の発動条件、TDDサイクル、テスト方針、完了報告を変更した場合は、この SPEC と README を同じ変更で更新します。誤検出、見逃し、テスト環境の問題、モック過多、テスト不能な経路の扱いで改善が必要になった場合は、発生条件と対応方針を追記します。
