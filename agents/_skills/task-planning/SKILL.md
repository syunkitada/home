# タスク計画

ユーザーの目的を、実装前に確認できる作業計画へ変換する。計画だけを依頼された場合は、コード、設定、コミットを変更しない。

## 使うとき

- 新機能、バグ修正、リファクタリング、設定変更を複数段階に分けるとき
- 要件、対象範囲、完了条件が曖昧なとき
- 既存の構成や利用経路を調べてから実装方針を決める必要があるとき

単純な一行修正や、すでに作業手順が明確な変更には、計画だけの skill として適用しない。

## 手順

1. ユーザーの目的、明示された制約、対象範囲、期限、期待する成果物を抜き出す。
2. 適用される `AGENTS.md`、README、仕様、既存の実装、テストを読み、既存の契約と利用経路を確認する。
3. 不明点を、実装方針を変えるものと、実装中に安全に決められるものに分ける。前者は仮定を置かず、必要ならユーザーに確認する。
4. 受け入れ条件を、観測可能な結果として列挙する。エラー、境界値、互換性、移行、ロールバックも必要に応じて含める。
5. 作業を、依存関係と検証可能な単位を持つ小さな手順へ分解する。各手順に対象、変更内容、完了条件を付ける。
6. リスク、未確認事項、変更しない範囲、必要な検証コマンドを明記する。
7. 計画、前提、未解決の質問、受け入れ条件を日本語で報告する。

計画中に実装上の問題を見つけても、ユーザーが実装を依頼していない限り変更を始めない。
