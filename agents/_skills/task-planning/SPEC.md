# タスク計画スキルの契約と設計根拠

このファイルは task-planning skill の適用範囲、計画の契約、出力方針、設計根拠を定義する保守契約です。実行時の詳細手順は [SKILL.md](./SKILL.md) に記載します。

## 適用範囲

対象は、実装前に要件や作業を整理する次の依頼です。

- 新機能、修正、リファクタリング、設定変更などを複数の作業へ分解する依頼
- 要件、対象範囲、完了条件、依存関係、実装順序が曖昧な依頼
- 既存の構成、利用経路、テスト、運用制約を調べて実装方針を決める依頼
- 複数の担当者やセッションへ、独立して検証できる単位で作業を引き渡す依頼

計画だけの依頼では、プロダクトのコード、設定、テスト、生成物、Git履歴、外部トラッカーを変更しません。保存を明示された計画文書とタスク一覧だけは、既存の未完了計画を確認したうえで作成・更新できます。

## 計画の契約

- 実装前に、ユーザーの目的、制約、対象範囲、完了条件、成果物を明確にする。
- `AGENTS.md`、README、仕様、既存実装、利用経路、関連テスト、CI、運用手順を読み取り専用で確認する。
- 確認済みの事実、計画上の仮定、実装方針を変える未解決事項を分け、重要な不明点を推測で埋めない。
- 受け入れ条件を観測可能な結果で定義し、必要に応じてエラー、境界値、互換性、移行、ロールバックを含める。
- タスクには成果物、対象範囲、依存関係、受け入れ条件、検証方法、規模を持たせる。
- タスクは独立して検証できる最小単位とし、可能な限り垂直スライスとして依存順に並べる。
- 高リスク箇所、共有契約、並行化の可否、段階ごとのチェックポイントを明記する。
- 計画文書を保存する場合も、異なる作業の未完了計画を確認なしに上書き、削除、統合しない。
- 計画から実装への引き渡し条件と、ユーザーのレビュー・承認が必要な点を報告する。
- 実装、テスト、完了検証、Git操作は、それぞれ対応する skill と明示的な依頼へ分ける。

## 対象外

- 単純で手順が明確な一行修正の計画化
- 仕様に検証可能なタスクと依存順序がすでに定義されている作業の再計画
- 計画だけの依頼におけるプロダクトコード、設定、テスト、生成物の変更
- ユーザーの確認なしの計画文書の上書き、削除、未完了タスクの一括クローズ
- 計画作成を理由にした commit、push、branch、PR、merge、release、外部トラッカー操作

## 維持・改善

`SKILL.md` の発動条件、計画手順、タスク形式、出力境界を変更した場合は、この SPEC と README を同じ変更で更新します。計画漏れ、依存順序の誤り、受け入れ条件や検証不足、未完了計画の上書きリスクが見つかった場合は、発生条件と対応方針を追記します。
