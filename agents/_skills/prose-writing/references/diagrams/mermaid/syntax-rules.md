# Mermaid構文エラー対策

Mermaidの構文は図種ごとに異なります。次の項目を確認したうえで、エラーが残る場合は対象図種の公式構文とレンダラーの対応バージョンを確認します。

## IDとラベル

- ノードIDは一意にし、接続では常にIDを使う。表示名をIDとして再利用しない。
- 空白や句読点、予約文字を含む表示ラベルは、対象図種の構文に沿って引用符で囲む。
- ラベル内に引用符や構文上予約された文字を含める方法は図種で異なる。Mermaidの[構文リファレンス](https://mermaid.js.org/intro/syntax-reference.html)で確認する。

## Flowchartの注意

- 小文字の `end` をノード名やラベルに使うと構文を壊す場合がある。別の語にするか、対象構文で引用する。
- 接続直後の `o`、`x` は、円・交差を表す接続記号として解釈される場合がある。該当するラベルを別の形で書く。
- グループ名に空白がある場合や、グループを接続先にする場合は、IDと表示名を分ける。例: `subgraph services["サービス"]`。
- 接続の説明には `A -->|成功| B` の形式を使い、矢印とラベルの区切りを明確にする。
- ラベル内の `1. 項目` などがリストとして解釈されてエラーになる場合は、`項目1` や `Step 1: 項目` のように書き換えるか、引用して再確認する。

## その他の確認

- コメントは対応する図種のコメント構文を使い、図の構文行と混ぜない。
- 括弧、角括弧、引用符などの組み合わせが閉じている。
- 要素を定義したIDと、接続で参照するIDが一致している。
- 図種宣言と、その後の構文が一致している。
- Markdown内ではフェンスを ```mermaid で開始し、正しく閉じている。

## エラーの切り分け

1. パーサーが示した行と、その直前の行を確認する。誤りの位置が直前のラベルや未閉じ括弧にある場合がある。
2. 装飾、長いラベル、複数の接続を一時的に除き、最小の図で原因を確認する。
3. 対象プラットフォームで同じ図を描画し、ホスト固有のバージョン差を切り分ける。
4. エラーが解消したら、要素や装飾を少しずつ戻して再確認する。

機能の有無や特殊文字の扱いを、すべてのMermaidホストで同一と仮定しません。
