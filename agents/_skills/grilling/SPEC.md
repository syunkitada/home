# grilling スキルの契約と設計根拠

このファイルは `grilling` skill の適用範囲、質問インタビューの契約、設計判断、参考資料、保守方針を定義します。実行時の詳細手順は [SKILL.md](./SKILL.md)、利用者向けの入口は [README.md](./README.md) に記載します。

## 適用範囲

対象は、計画、設計、意思決定について、実装前にユーザーとの共通理解を作る必要がある依頼です。

- ユーザーが設計や計画を厳しく検証するよう求める依頼
- 判断の依存関係を整理し、質問の順番を管理する必要がある依頼
- 目的、対象範囲、制約、失敗時の扱い、未決定事項を対話で明確にする依頼

単純な修正、仕様確定済みの実装、レビュー、調査、説明だけの依頼を、理由なく質問ラウンドへ変換しません。実装、テスト、完了検証、Git操作は、それぞれ対応する skill と明示的な依頼へ分けます。

## 公開インターフェース

| 項目 | 契約 |
| --- | --- |
| skill名 | `grilling` |
| 発動条件 | ユーザーが設計・計画・判断のストレステストや質問による深掘りを求めたとき |
| 質問単位 | 前提が確定した判断だけを frontier として、依存順にラウンドで提示する |
| 質問内容 | 判断はユーザーに確認し、確認可能な事実はツールで調査する |
| 推奨案 | 各質問に必要に応じて推奨案と理由を示すが、ユーザーの判断を置き換えない |
| 保留 | 保留、後回し、対象外を明示的な状態として扱う |
| 完了条件 | 対象範囲に関係する重要な判断を整理し、共通理解を要約してユーザーの確認を得る |
| 変更境界 | ユーザーの確認前にコード、設定、テスト、文書、外部状態を変更しない |
| 引き渡し | 実装が必要なら `task-planning` または `implementation` に渡す |

## 設計判断

### 独立した対話モードにする

既存の [`task-planning`](../task-planning/SKILL.md) は、要件を実装可能な計画、受け入れ条件、検証方法へ整理する skill です。`grilling` はその前段で、ユーザーとの質問と判断のループを担当します。責務が異なるため、`task-planning` に統合せず独立させ、必要なときだけ組み合わせます。

### 依存順の frontier を使う

下流の判断を先に質問すると、未確定の前提に基づく回答になり、質問のやり直しが増えます。現在回答できる質問だけを frontier として扱い、回答後に次の frontier を計算することで、質問の順序を判断木に合わせます。

### 質問数を制御し、保留を許可する

原資料の「frontier 全体を1ラウンドで質問する」方針は採用しますが、質問が多い場合は重要度と依存関係を優先して分割します。また、すべての判断をその場で確定できるとは限らないため、保留・対象外・後回しを明示的に扱います。

### 事実調査を sub-agent の必須条件にしない

原資料は環境上の事実調査を sub-agent に委譲するよう指示しています。このリポジトリでは利用可能なツールで確認できる事実をエージェントが調査することを契約とし、特定の sub-agent 機能には依存させません。

### 確認を実装のゲートにする

質問の回答を得ただけでは、ユーザーが要約内容に同意したとは限りません。最終要約を提示して明示的に確認を得るまでは変更を始めず、確認後に実装系 skill へ引き渡します。

## 保守方針

- `SKILL.md` の発動条件、質問手順、完了条件、変更境界を変更した場合は、READMEとこのSPECを同じ変更で更新します。
- `task-planning`、`implementation` など既存 skill との責務境界を変更した場合は、相互リンクと引き渡し条件を確認します。
- 外部資料を追加・更新した場合は、URL、参照リビジョン、参照箇所、採用内容をこのSPECに記録します。外部リポジトリを実行時依存にしません。
- 質問過多、順序の誤り、推奨案の押し付け、確認前の変更などの具体的な問題が再現した場合だけ、発動条件や手順を狭く修正します。
