# Git ワークフロー

Git を作業の保存点、変更範囲、履歴、協業境界として扱う。ユーザーが明示した操作だけを実行し、無関係な変更や履歴を壊さない。

## 共通手順

1. `git status --short`、現在のブランチ、追跡先、直近の履歴を確認する。
2. `git diff` と `git diff --cached` を分けて読み、ユーザーの対象範囲と既存の作業を区別する。
3. 関連する仕様、テスト、レビュー結果、検証結果を確認してから履歴操作を行う。
4. 操作対象、比較元、生成される履歴、外部へ影響する操作をユーザーに分かる形で確認する。
5. 操作後に status、diff、log、必要な検証結果を確認し、実際の状態を報告する。

## 操作別の方針

### ブランチ

- 既存の未コミット変更を確認してから作成、切り替え、削除を行う。
- ブランチ名と目的を明確にし、無関係な変更を別のブランチへ混ぜない。
- 切り替えで変更が失われる可能性がある場合は、先に停止して確認を求める。

### コミット

- 一つの論理的な目的ごとに小さくまとめ、コミット前に staged diff を読む。
- メッセージは変更内容ではなく目的が分かる短い命令形にし、リポジトリの規約があれば従う。
- ユーザーがコミットを求めていない場合は、コミットを作成しない。

### PR、push、release

- base、head、対象コミット、検証結果、差分の範囲を確認してから作成・更新する。
- push、PR 作成、merge、tag、release は外部状態を変えるため、ユーザーの明示的な依頼なしに実行しない。
- force push、履歴書き換え、広範囲の削除や reset は、対象、影響、復旧方法を確認せずに行わない。

### merge conflict

- 競合前後の意図と両側の変更を読み、機械的に片側を採用しない。
- 解消後に競合マーカー、差分、関連テストを確認し、解消内容を報告する。
