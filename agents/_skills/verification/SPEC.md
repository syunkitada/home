# 完了前検証スキルの契約と設計根拠

このファイルは verification skill の適用範囲、証拠基準、検証と報告の契約、設計根拠を定義する保守契約です。実行時の詳細手順は [SKILL.md](./SKILL.md) に記載します。

## 適用範囲

対象は、作業完了、修正完了、テスト成功、要件充足などの主張を、現在の変更状態と新しい確認結果で裏付ける次の依頼です。

- 実装、修正、設定変更、文書・構成変更の完了確認
- テスト、型検査、lint、build、起動確認、リンク・構文・配置確認
- 要件、受け入れ条件、差分、作業ツリー、未確認事項の照合
- レビュー結果や他のエージェントの報告を、独立した証拠で確認する作業

検証だけの依頼では、プロダクトのコード、設定、テスト、生成物を変更しません。失敗の修正、原因究明、レビューそのものは、それぞれ対応する skill へ分けます。

## 検証の契約

- 完了を主張する前に、主張ごとに必要な証拠と検証方法を定義する。
- 現在の変更状態で新しい検証を実行し、過去の結果や変更した事実だけで成功を推測しない。
- `AGENTS.md`、README、仕様、チケット、計画、実装、利用経路から対象範囲と完了条件を固定する。
- `git status` と `git diff` で、ステージ済み、未ステージ、未追跡、生成物、意図しない変更を区別する。
- プロジェクトの標準コマンドを発見し、最も狭い有効な検証から関連経路・全体検証へ広げる。
- コマンドの終了コードと出力を読み、確認できた主張、失敗、未確認事項を分ける。
- テスト成功を、未実行経路、要件全体、境界条件の証明として過大解釈しない。
- 文書・構成変更では、リンク、構文、Index、配置、ファイル一覧を検証対象にする。
- 実行できない検証は、理由、代替確認、残るリスクを報告する。
- 失敗を隠すための実装変更、破壊的な環境準備、無関係な外部状態変更を行わない。
- 完了報告には、検証コマンドまたは確認方法、終了コード、出力、対象範囲、未確認事項を含める。

## 対象外

- 検証結果を受けたバグ修正や実装変更。変更は `implementation`、挙動のテスト駆動は `tdd` を使う。
- 原因究明だけを目的とする診断。再現と切り分けを別の依頼として扱う。
- レビューだけを目的とする依頼。差分の不具合・回帰評価は `code-review` を使う。
- 検証を理由にしたcommit、push、branch、PR、merge、release、外部サービスへの更新。
- 現在の変更と関係のない全体テストだけを、完了の根拠にすること。

## 維持・改善

`SKILL.md` の証拠基準、検証手順、対象範囲、報告形式を変更した場合は、この SPEC と README を同じ変更で更新します。誤った完了主張、検証漏れ、過剰な全体テスト、未追跡ファイルの見逃しが見つかった場合は、発生条件と対応方針を追記します。
