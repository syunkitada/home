# セッション振り返り

現在のセッションを振り返り、次回以降の作業に役立つ改善候補を提案する skill です。会話、実行結果、差分、関連する skill・設定・作業文書を根拠に、既存skillの更新候補、新規skillへの切り出し、既存ツールの改善・新規ツールの開発候補を含めて、改善対象、影響、分類、優先度、確信度、次のアクションを整理します。明示依頼では、指定された過去ログを安全に読み取る手順も使います。

skill、設定、文書、コード、ツールを直接変更せず、改善案と実装計画までを扱います。実装は別途 `implementation`、完了確認は `verification` に引き渡します。

## Index

| パス | 役割 |
| --- | --- |
| [SKILL.md](./SKILL.md) | 発動条件、調査対象、改善候補の分類、レポート形式、境界 |
| [SPEC.md](./SPEC.md) | 適用範囲、公開契約、設計根拠、保守方針 |
| [`references/`](./references/) | ユーザー指定の過去ログを扱うときの同定、読み取り、秘密情報のマスキング、安全な出典記録 |
| [`evals/`](./evals/) | 外部 runner を使わずに確認する手動評価ケース |

## 利用例

~~~text
$session-retrospective 今回のセッションを振り返り、skill・設定・作業文書・ツール利用の改善案を優先度順に出してください。
~~~

通常の作業が明確に完了したときは、現在の会話と関連ファイルだけを確認する軽量モードで動きます。明示的に過去ログを指定する場合は、パスを示して対象を限定してください。会話、ファイル、差分、コマンド、ログなどすべての証拠は、秘密情報・個人情報・機密パスをマスキングしてから出力します。記録は会話への出力のみで、専用ログは作成しません。

## 維持・改善

`SKILL.md` の発動条件、対象範囲、分類、出力契約、変更境界を変更した場合は、この README と [SPEC.md](./SPEC.md) の説明を同期します。過去ログの扱いを変更した場合は [references/](./references/) も更新し、評価ケースを追加・変更した場合は [evals/](./evals/) とこの Index を同期します。誤検出、見逃し、根拠不足、過剰な提案が実際に見つかった場合は、発生条件と対応方針を SPEC に追記します。
