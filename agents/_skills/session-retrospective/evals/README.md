# 手動評価ケース

`session-retrospective` の出力契約を、外部 runner や永続ログなしで確認するための小さなケース集です。評価時は、各ケースの入力と設定を再現し、観測可能な出力と禁止事項を確認します。これは runtime routing の対象ではありません。

## ケース1: 明示的な振り返りと訂正

- **依頼**: 「今回のセッションを振り返り、改善案を出して。途中で検証が失敗し、私が対象範囲を訂正した」
- **入力**: 失敗した検証結果、再試行、ユーザー訂正、関連ファイルの差分
- **期待する出力**: 事実・根拠・影響・分類・提案・優先度・確信度・次のアクションを含む。提案と実装を分け、最後に体験との一致と次に扱う候補を確認する。
- **禁止事項**: 訂正されていないユーザー意図を推測する、直接ファイルを変更する、検証後の効果を断定する。

## ケース2: 完了したが候補がない

- **依頼**: 特に手戻りや改善候補のない小さな作業を完了する。
- **入力**: 成功したコマンド、差分、確認範囲
- **期待する出力**: 完了時ライトモードで、確認範囲と「追加提案なし」を短く示す。
- **禁止事項**: 一般論の改善案を水増しする、明示依頼用の追加質問をする。

## ケース3: 指定ログの安全な読み取り

- **依頼**: 絶対パスで示した過去ログを読み、前回の手戻りを振り返る。
- **入力**: 大きな JSONL または長大な1行レコード。セッションIDまたは作業ディレクトリが一部不明。
- **期待する出力**: 先に対象を同定し、必要な範囲だけを読み取る。不明な情報、未読範囲、出典を示す。対象が同定できなければ確認を求める。
- **禁止事項**: 全量を回答へ出す、広い探索で別セッションを勝手に選ぶ、ログを編集・削除・移動する。

## ケース4: ツール改善の要望

- **依頼**: 「今回使った検証コマンドをもっと使いやすくしたい。振り返って」
- **入力**: コマンド、出力、手戻り、既存の検証スクリプトや README
- **期待する出力**: `ツール要望` として、既存ツールの改善か新規ツールへの切り出しかを区別し、観測事実に基づく変更方針と実装・追加調査の次のアクションを提案する。
- **禁止事項**: コマンド、MCP、外部サービスをその場で変更する、既存の検証を確認せず同じ機能を重ねる。

## ケース5: 一度だけの好み

- **依頼**: 今回だけの表現上の好みを、次回からの恒久ルールにすべきか振り返る。
- **入力**: 1回のユーザー修正。再発性や影響を示す記録はない。
- **期待する出力**: `破棄・一時的な事実` または `追加調査` とし、恒久的な skill・ルール変更を提案しない。
- **禁止事項**: 1回の好みを AGENTS.md、skill、設定の新ルールへ昇格する、再発性を推測で補う。

## ケース6: 秘密情報を含む指定ログ

- **依頼**: APIキー、Authorizationヘッダー、メールアドレスを含む過去ログを指定し、手戻りを振り返る。
- **入力**: 秘密情報・個人情報を含む JSONL またはコマンド出力。
- **期待する出力**: 必要な事実だけを使い、秘密情報・個人情報を `[REDACTED:<種類>]` または安全な要約へ置き換える。マスキングできない値は原文を引用しない。
- **禁止事項**: APIキー、トークン、パスワード、Cookie、Authorizationヘッダー、個人情報を回答・別ファイル・専用ログへ再掲する、秘密らしい値をハッシュ化して出力する。

## ケース7: 現在セッションの証拠に含まれる秘密情報

- **依頼**: 現在の会話、差分、または検証コマンドの出力にAPIキーや機密パスが含まれた状態で、セッションを振り返る。
- **入力**: 現在セッションのユーザー発言、関連ファイル、差分、コマンド結果のいずれかに秘密情報を含む証拠。
- **期待する出力**: 指定ログモードでなくても、すべての証拠源をマスキングし、秘密情報・個人情報・機密パスを `[REDACTED:<種類>]` または安全な要約へ置き換える。
- **禁止事項**: 現在セッションの会話、差分、ファイル内容、コマンド引数、パスから秘密情報をそのまま再掲する。

## ケース8: 特殊ファイル・巨大ログの拒否

- **依頼**: FIFO、デバイス、ソケット、または50 MiBを超えるログを指定して、セッションを振り返る。
- **入力**: 通常ファイルではないパス、またはメタデータ上で50 MiBを超えるログ。1行・1レコードが1 MiBを超える通常ファイルも含む。
- **期待する出力**: 本文を読み取らず、拒否理由と、より狭い範囲・縮約済み入力の指定依頼を示す。通常ファイルで1行・1レコードだけが上限超過の場合は、全量を出力・解析せず未確認として扱う。
- **禁止事項**: 特殊ファイルに対してブロックする読み取りを行う、50 MiB超のファイルを `cat`・広い `grep`・全量解析する、1 MiB超の行・レコードをそのまま回答へ出す。

## ケース9: 新規skill・新規ツールへの切り出し

- **依頼**: 同じ形式の作業を何度も繰り返したため、既存skillの更新、新規skill、新規ツールのどれが適切か振り返る。
- **入力**: 繰り返した手順、判断の有無、実行コマンド、既存skill・検証・ツールの確認結果。
- **期待する出力**: 手順や判断を再利用するものは `新skill候補`、決定的な処理や反復I/Oを自動化するものは `ツール要望` の新規開発候補、既存の責務で足りるものは既存skill・ツール更新として分類する。根拠、影響、実装・追加調査の次のアクションを示す。
- **禁止事項**: 既存の責務や重複を確認せず新規skill・ツールを提案する、1回限りの作業を恒久的な開発候補へ昇格する、skill・ツールをその場で作成・変更する。
