# コードレビュースキルの契約と設計根拠

このファイルは code-review スキルの対象範囲、証拠基準、報告形式を定義する保守契約です。参考資料、採用内容、自分用の調整、未解決の評価課題もここで管理します。取得した参照リポジトリは実行時依存ではありません。

## 対象範囲

対象は、ユーザーがレビューを依頼した次の変更です。

- 未コミットの作業ツリー変更
- ステージ済みまたは未ステージの差分
- 単一コミット、コミット範囲、ブランチ、PR
- 実装後のセルフレビュー

ユーザーが比較範囲を指定した場合は、その範囲を優先します。指定がない場合に限り、作業ツリーの未コミット変更全体を対象にします。

## 対象外

- レビュー依頼だけを根拠にした修正、コミット、push、PR 投稿
- 変更と因果関係のない既存問題の全面監査
- 課題管理ツール、特定のホスティングサービス、並列サブエージェントの必須化
- フレームワーク固有のチェックを、該当しない変更へ一律適用すること

## 証拠方針

確定した指摘には、変更された場所、発生条件、影響、根拠、確信度を必要とします。根拠は再現結果、テスト結果、または具体的なコード経路のいずれかです。確信度は、高（再現または失敗テストで確認）、中（具体的なコード経路で確認）、低（未検証の仮定）で示します。低確信度の懸念は確定した指摘とせず、未解決事項として報告します。

レビューでは、仕様と既存の利用経路の両方を読みます。テストが通ったことだけで、別の境界条件や未実行経路の安全性を証明したとは扱いません。

## 指摘の契約

重要度は P0 から P3 とし、重大性を発生条件から切り離して誇張しません。各指摘に重要度と確信度を記載し、重要度、確信度、影響の順に並べます。同じ原因の指摘はまとめます。

指摘がない場合も、比較範囲、参照した根拠、実行した検証、未確認事項を出力します。

## このリポジトリ向けの調整

- 並列サブエージェントは必須にしない。現在の作業環境では、対象範囲と検証結果を一つのレビューで追跡できることを優先する。
- 課題管理ツールや GitHub CLI は必須にしない。ユーザーが仕様や PR 情報を提示した場合だけ利用する。
- PR の base/head を解決できない場合は、現在の HEAD を代用せず範囲エラーとして扱う。
- Sentry の Django・React 例は汎用チェックリストへ一般化し、該当する変更だけを確認する。
- P0 から P3 の重要度と日本語での報告は、このリポジトリの既存スキルの契約を維持する。
- 実行時に使う参照資料は SKILL.md から相対リンクし、報告には確信度を含める。

## 保守

発動条件、対象範囲、証拠基準、出力形式、参考資料に基づく設計を変更したときは、この SPEC を更新します。実際の誤検出・見逃し・改善例が蓄積した場合は、references/evidence/ を追加して作業用集合と保留検証集合を分離します。

## 未確認事項と次に集める証拠

まだ実際の利用ログから抽出した誤検出・見逃しの保留検証例はありません。次の3ケースを実利用で確認し、必要なら references/evidence/ に匿名化して保存します。

1. ステージ済みと未ステージ変更が同じファイルにあるケース
2. テストは通るが仕様に違反するケース
3. 問題がなく、過剰な指摘を避けるケース
