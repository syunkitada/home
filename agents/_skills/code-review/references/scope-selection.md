# 対象範囲の選択

レビュー前に、依頼された比較範囲と、実際に読む対象を一致させる。比較元を指定された場合は、その参照を git rev-parse で解決し、レビュー中は解決後の SHA を使う。PR は、ユーザーが示した base/head、またはローカルで利用できる PR の参照から両方を解決する。PR 番号だけでは解決できない場合は、現在の HEAD を PR の head と推測せず、範囲エラーとして報告する。

## 対応表

| 依頼 | 比較方法と読むファイル |
| --- | --- |
| 比較範囲を狭めない未コミット変更 | git diff HEAD。ステージ済み・未ステージの追跡ファイルを含め、git status --short で未追跡ファイルも確認する |
| ステージ済み変更だけ | git diff --cached。同じパスの未ステージ変更ではなく、index の版を読む |
| 未ステージ変更だけ（未追跡を除く） | git diff。ステージ済みだけの変更と未追跡ファイルは含めない。未追跡も求められた場合は git status --short から個別に読む |
| 基準ブランチに対するブランチ | 基準を解決し、git diff <base>...HEAD と git log <base>..HEAD --oneline を使う |
| PR（base/head を解決できる場合） | 解決した base/head をそれぞれ SHA に固定し、git diff <base>...<head> と git log <base>..<head> --oneline を使う |
| PR の base/head を解決できない場合 | 対象範囲エラーとして報告し、現在の HEAD を代用しない |
| 1コミット | そのコミットと第1親を比較する。ブランチ全体を暗黙にレビューしない |
| 明示された範囲 | 指定された範囲をそのまま使い、両端を明記する |

名前付きの範囲とローカル変更が同時に指定された場合、ユーザーが明示的に両方を求めない限り、2つの範囲を分けて扱う。レビュー中にブランチ切り替え、ファイルの reset、コミット作成を行わない。

## 境界の確認

- 不正な参照は対象範囲のエラーであり、実装上の指摘ではない。
- 差分が空であることは報告すべき結果であり、指摘を作る理由にはしない。
- git diff は未追跡ファイルを表示しない。選択した範囲に含まれる場合だけ個別に読む。
- ステージ済みだけをレビューするとき、周辺コンテキストが必要なら git show :path など index を読めるコマンドを使う。
- ブランチをレビューするとき、既存の無関係な作業ツリー変更をブランチの一部として扱わない。
