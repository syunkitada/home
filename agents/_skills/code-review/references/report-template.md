# レビュー報告テンプレート

ユーザーが別の形式を指定しない限り、次の構成を使う。

~~~markdown
## 指摘

### P1: 問題を短く表す見出し

- 場所: 対象ファイル:行
- 確信度: 高 / 中 / 低
- 発生条件: 必要な入力、状態、環境
- 影響: 影響を受ける利用者、データ、権限、処理
- 根拠: 再現結果、テスト結果、コード経路の説明
- 修正方針: 明確な場合の、対象を絞った対応案

## 範囲と検証

- 比較対象: 固定した比較元と解決後の SHA
- 読んだ根拠: 仕様、規約、呼び出し元、テスト
- 実行した確認: コマンドまたはテスト
- 未確認: 残った仮定または実行できなかった確認
~~~

## 重要度

- **P0**: 広範囲の停止、不可逆なデータ損失、または直ちに対応が必要なセキュリティ侵害。
- **P1**: 主要な機能、データ、権限、互換性に関わる、発生可能性の高い破壊。
- **P2**: 現実的な条件で発生する、範囲の限定された不具合または要件不一致。
- **P3**: 影響は小さいが、証拠があり修正に価値のある問題。

指摘は重要度、確信度、影響の順に並べる。未検証の懸念を重要度で誇張しない。

確信度は、高（再現または失敗テストで確認）、中（具体的なコード経路で確認）、低（未検証の仮定）で示す。低確信度の懸念は確定した指摘ではなく、未確認事項として扱う。

指摘がない場合は「確認した範囲では指摘なし」と書き、範囲、検証、未確認事項も含める。
